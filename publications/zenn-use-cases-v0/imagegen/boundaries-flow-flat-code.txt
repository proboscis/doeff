コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し:文書取得・Memo保存・HTTP・時計を別々に組む

図:白背景の平面的な処理図。上部または左に4行コードを正確に載せる。主経路は「ReadPageの依頼」→「メモ化の判定」。判定枠から上の「Memo保存のハンドラ」へ照会し、保存ヒットなら「保存した本文」から依頼元へ返す。保存ミスなら「ReadPageからHTTPへ翻訳」→「HTTPのハンドラ」→「取得した本文をMemoへ保存」→依頼元へ本文を返す。Memo保存の担当は1つの枠として描き、メモリかSQLiteを選ぶことを短く記す。HTTP担当は「固定応答 / 本番 / 拒否から選ぶ」で、選択肢を同時並行に動かす矢印にしない。右下の独立した「時計のハンドラ」から固定HTTP担当のDelayを扱う関係を点線で示す。時計の選択肢は「仮想時間 / 実時間」。小注記に「例の固定HTTP: 初回2ページを並行取得で2秒、次は新規1ページで2秒。合計3件・仮想4秒」と置く。保存ヒットからHTTPやDelayへ矢印を引かない。写真・3D禁止。
説明:ReadPageの保存ヒットなら本文を戻し、保存ミスならHTTPへ翻訳して取得後に保存します。時計は取得待機を扱い、索引のProgramは共通です。
指定したAPI以外を創作しない。保存ヒットではHTTPへ進まず、依頼元へ値を返すことを厳守。
