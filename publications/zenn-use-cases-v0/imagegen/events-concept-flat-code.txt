Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し:型のあるイベントで、処理をつなぐ
コード:
listener = yield Spawn(receive_ready())  # Readyの受信を開始
yield Publish(Ready("準備完了"))  # 待機中の購読者へ通知
return (yield Wait(listener))  # 「準備完了」を受け取る
図:白背景、ネイビー文字、ティールの平面ダイアグラム。写真・立体物・台座・3D・ガラスの装飾は使わない。左上にコメント付きコードを正確に表示する。下に2本のレーンを描く。親workflowのSpawnから子receive_readyへ矢印、子はWaitForEvent(Ready)で「購読を登録して停止」へ。親のPublish(Ready("準備完了"))からevent_handlerを経由し、その待機点へ通知の矢印。子はevent.messageを返す→親のWait(listener)が「準備完了」を受け取る。現行スケジューラの同じ標準優先度では子が先に登録へ進む例であることを小さく明記。通知先は既に待っている購読者。発行前のイベントを保存するキューやDBは描かない。
説明:待機を繰り返しポーリングする代わりに、イベントが届いたら続きを動かします。
