Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し: 保存ヒットはHTTPを通らず、保存ミスだけ取得担当へ進む
コード:
second = make_memo_rewriter(HttpRequest)(fetch_text(url))  # 同じ依頼
second = sqlite_memo_handler(database)(second)  # 保存済み応答を照会
second = reject_http(second)  # 未保存のHTTP依頼は失敗
図の意味と流れ: 白背景の平面的な処理図。写真・3Dは禁止。上部に正確な3行のコード、下部に保存あり/なしの分岐。開始「同じURLを取得」→「SQLiteに保存済み？」。はい→「MemoGet」→「本文を返す：記録した本文」。いいえ→「HttpRequestを外側へ委譲」→「reject_http」→「LookupError（未保存のURL）」。はいの経路からreject_httpへ矢印を引かない。二つの経路は条件によって一方だけ通る。右下に小さい注記「取得を許すなら、reject_httpをfixed_httpや標準HTTPに交換」と記載する。HTTP clientやMockTransport、client_factoryは図中に入れない。
説明: 保存ミス時の取得・拒否をHTTPハンドラで切り替え、得た応答の保存をMemoハンドラへ任せます。
