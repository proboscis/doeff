Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し:異なる抽象を、同じyieldでつなぐ
コード:
outcome = yield Try(convert_title(text))  # 成功か失敗を受け取る
count = yield Get("attempts")  # 試行回数1を読む
messages = yield writer_log()  # 開始ログを受け取る
return outcome, count, messages  # 結果・回数・ログを返す
図:白背景、平面的な角丸枠、紺文字、青緑の矢印。写真・3D不可。中央に4行のコードを大きく配置する。上から順にコード行へ対応する枠を置く。Tryの行は『変換の結果 → Ok / Err』、Getの行は『State → 試行回数1』、writer_logの行は『Writer → 開始ログ』。最後のreturnの行から『結果・回数・ログ』へ矢印を出す。上部の補助枠で『変換の中では Ask → 設定2秒、Delay → 仮想時間で待機』と表示し、変換の処理に接続する。抽象ごとに別の構文を必要とせずyieldで結果を受け取ることを示す。ハンドラの並列実行や、失敗時の状態リセットは描かない。コードの各行のコメントも必ず表示する。コードは抜粋と明記。
説明:Tryで成功・失敗を値にし、Getで状態、writer_logでログを受け取ります。設定や時間も子Programの中で同じyieldを使います。
矢印は意味が確かなものだけ。結果の一覧は独立したカードにして不要な矢印を引かない。
