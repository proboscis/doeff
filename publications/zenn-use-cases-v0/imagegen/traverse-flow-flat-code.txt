Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し:文書ごとの計算と、失敗・集計の方針を分ける
コード:
lengths = yield Traverse(read_length, texts)  # 2・失敗・7
total = yield Reduce(add, 0, lengths)  # 成功分を足して9
history = yield Inspect(lengths)  # 3件の履歴
return total, history  # 合計と成否を返す
図:白背景の平面的な説明図。3D・実写・立体台座は禁止。コードは@do関数内の抜粋であると枠の外に明記。入力「短文」「空文字」「もう少し長い文」からread_lengthへ矢印。正常2件は2と7、空文字はFail(ValueError)へ。Failは共通の内側fail_handlerでValueErrorへ変わる。その次に外側の実行戦略を2択として示す。選択肢parallel(concurrency=2)では履歴[成功2, 失敗, 成功7]へ進み、Reduceは成功値2+7=9、Inspectは3件の履歴を返す。もう一方parallel_fail_fast(concurrency=2)ではValueErrorが呼び出し元へ届き全体が中断する。2択は同時実行する枝ではないと注記。失敗を0文字や成功値へ変換して描かない。
説明:`parallel`では2・失敗・7を履歴に残し、`Reduce`が成功分を合計して9を返します。`parallel_fail_fast`を選ぶと、同じ空文書の例外が全体へ伝わります。
