Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し: 画像を生成し、その結果を編集へ渡す
コード:
generated = yield generate_cover(model)  # ImageResultを受け取る
edited = yield brighten_cover(generated, model)  # imagesを次へ渡す
return edited  # 編集後のImageResultを返す
図の意味と流れ: 白背景の平面的なシーケンス図。列は「制作Program」「画像ハンドラ」。上から ImageGenerate依頼 → ハンドラ → ImageResultを返して再開 → generated.imagesを保持 → ImageEdit(images=generated.images)依頼 → ハンドラ → 編集後のImageResultを返して再開 → return edited。図の上か左に3行コードを等幅で掲示し、行1・行2・行3を対応工程へつなぐ。依頼の矢印と結果の矢印を区別。小さな注記「固定ハンドラで、同じ画像リストが編集へ届くことを確認」。画像品質の改善を描く必要はない。生成と編集の並列実行を描かない。写真・3D・立体物禁止。
説明: 生成ハンドラがImageResultを返すと、生成を待っていた処理が再開します。そのimagesを編集依頼へ渡し、編集後のImageResultを後続へ返します。
