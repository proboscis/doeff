Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し: 2件のレビューを開始し、結果を待って可否を合成する
コード:
language = yield Spawn(checked_review(language_spec, timeout_seconds))  # 文章を開始
examples = yield Spawn(checked_review(example_spec, timeout_seconds))  # コードを開始
language_result = yield Wait(language)  # 文章の結果を取得
example_result = yield Wait(examples)  # コードの結果を取得
図の意味と流れ: 白背景、濃紺と青緑の平面ダイアグラム。左上に4行のコード抜粋。右上の『Spawnを2回』から『文章のレビュー』『コードのレビュー』に分岐し、それぞれ『AwaitResult』→『結果の確認・ReleaseSession』→『Waitの結果』。文章の返り値『ok=True』、コードの返り値『ok=False』を大きく示す。最後に両方の矢印が『True and False』へ合流し『ready=False』に向かう。図の下に『エージェントの応答はシナリオ』『@doとスケジューラ、判断処理を実行』と明記。コード4行の後で、本文のreturnにある2結果のokの論理積を取ることを図で説明。1タスクの完了後にもう1タスクを起動する直列図にしない。写真や3Dは禁止。
説明: 2件を開始してから、それぞれの結果を待ちます。シナリオ例は文章がok=True、コードがok=Falseなので、最終結果はready=Falseです。
