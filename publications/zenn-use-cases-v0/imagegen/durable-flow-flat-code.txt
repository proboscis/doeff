Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し:3つのプロセスで、完了結果を引き継ぐ
コード:
@do  # 解析と見出し抽出を合成する
def finish():  # 全体を先頭から実行する
    lines = yield prepare()  # 保存済みなら解析3行を取得
    return (yield make_outline(lines, "outline-v1"))  # 見出し2行を返す
図:白背景の平面的な処理図。上に4行のコメント付きコード、下は左から順に「プロセス1: prepare」「プロセス2: finish」「プロセス3: finish」の3列。プロセス1は「解析を計算・保存」だけ、見出し抽出を描かない。プロセス2は「解析の保存結果を取得」→「見出しを計算・保存」。プロセス3は「解析の保存結果を取得」→「見出しの保存結果を取得」。3列に共通するSQLite結果保存先を最下部に配置し、保存と取得の矢印に名前を付ける。各プロセスは前のプロセスが正常終了してから起動する。戻り値は順に「解析3行」「見出し2行」「同じ見出し2行」。実行中の継続を引き継ぐ矢印を描かない。最大限単純に、写真・3D不可。
説明:初回は解析だけを保存し、2回目は解析結果を使って見出しを保存します。3回目は両方の結果を再利用して、同じ見出しを返します。
矢印は意味が確かなものだけ。値の受け渡し方向は厳密に守る。
