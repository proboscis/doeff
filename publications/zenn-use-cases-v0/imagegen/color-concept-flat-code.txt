Use case: infographic-diagram. 日本語技術記事の完成ダイアグラム。添付は表現トーンの参考のみ。全面が不透明な白、ネイビーの日本語、ティールの明瞭な矢印、薄い青/ミント/紫の平面的な角丸枠。写実・3D・金属・ガラス・立体的装置・台座・装飾的なイラストを禁止。横長3:2。図中に下記の短いコードを大きく正確な等幅文字で配置し、対応する操作や流れと矢印で結ぶ。大きいタイトル、余白、最大6ノード程度。日本語の説明を短く、コードは改変しない。原稿からの抜粋なので小さく「コードは抜粋。完全な例は本文へ」。以下の意味を守り、勝手な挙動や架空のAPIを追加しない。
コードは提供されたもののみ。コード各行の日本語コメントも省略せず表示。機械的な循環矢印や図にないAPIを追加しない。
見出し:処理をつなぐ書き方をProgramへ揃える
コード:
@do  # 設定取得と子の待機処理を、ひとつのProgramへ合成する。
def workflow(seconds: float):  # 3種類の時計で共有する処理の順序を表す。
    prefix = yield Ask("result_prefix")  # この実行範囲の設定から「処理結果」を受け取る。
    result = yield worker(seconds)  # 子のProgramを進め、待機後に「完了」を受け取る。
    return f"{prefix}: {result}"  # 設定と子の結果を使い、「処理結果: 完了」を返す。
図:白背景の平面的ダイアグラム。ネイビー文字・ティールの矢印・淡い角丸枠。左または上に正確な5行コード。右または下の主経路は「設定を依頼」→「prefix = 処理結果」→「子Programをyield」→「result = 完了」→「処理結果: 完了」。設定を依頼の下に小さく「lazy_ask」、子Programの下に小さく「workerがDelayを依頼」とラベルを置く。下部に「Delayの解釈を選ぶ」と3つの平たい選択肢「同期の実時間」「非同期の実時間」「仮想時間」。この3つは同時実行ではなく、実行ごとに1つを選ぶと明記。Askを時間ハンドラが処理するようには描かない。コード各行のコメントを含め、3D・写実・立体の装置は禁止。
説明:設定の取得も子の計算もyieldでつなぎ、時間の依頼をどう扱うかは外側のハンドラで選びます。
