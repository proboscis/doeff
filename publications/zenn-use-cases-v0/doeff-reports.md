Claude Codeに図つきの報告のページを頼むと、筆者の環境では開くまで42分かかっていました。ページ作りを丸ごと任せるのをやめ、中身・HTML・図の3つに分けると、次に試した報告は5分36秒で開きました。中身は話していた会話が書き、HTMLは決まったスクリプトが組み、図だけを別の作業役が描きます。

前の形では、ページ作りを丸ごと、頼んだ会話とは別の作業役に任せていました。作業役は、頼んだ会話の文脈を持っていません。2026年9月30日の夜の報告で、42分の内訳は次のとおりでした。

- 作業役が、コードとissueを読み直すのに15.7分
- 作業役が、本文と図を書くのに3.5分
- 作業役が、ページ全体のスクリーンショットを撮って確かめるのに12分
- 出来たページが、誰にも開かれずに置かれていたのに9.5分

本文と図を書く時間は、3.5分だけでした。しかも最初のページは読みにくく、書き直して読める物になるまで74分かかりました。

会話はClaude Codeの1つのセッションで、作業役は会話が起こすサブエージェントです。この記事は、報告のページを3つの役に分けた記録です。ページを組む処理は、doeffで書いて見せます。doeffは、処理の中の「読む」「頼む」といった操作を、外側の部品で差し替えられるPythonのライブラリです。doeffが初めての方は[doeffの連載の1本目](doeff-main.md)から、コードは[GitHub](https://github.com/proboscis/doeff)から読めます。

## まず短いコード — 図が無くても、ページを組む

ページの中身は、会話がmarkdownのファイルに書きます。図を置きたい所には、図そのものではなく「図の指定」を書きます。ページを組む処理は、図の指定ごとに「描き終えた図をください」と外側へ依頼します。

```python
import re  # 中身のファイルから、図の指定の囲みを探す。
from dataclasses import dataclass  # 依頼を、書き換えないデータ型で表す。

from doeff import Effect, Pass, Resume, do, handler, run, with_handlers  # 依頼・再開・委譲と実行を使う。

FIGURE = re.compile(r"^~~~図 ([a-z0-9-]+)\n.*?^~~~\n", re.M | re.S)  # 「~~~図 <id>」から閉じの「~~~」までの囲み。
CONTENT = """\
# 検索の応答が遅くなった件

10月12日の夜の、検索の応答の報告です。決めてほしい事はありません。

## 結論

- 遅くなったのは、索引を作り直した後の30分だけでした。

~~~図 fig-1
題: 作り直しの前後の応答の秒
使う数字: 21時 0.2秒・22時 3.1秒・23時 0.2秒
~~~

~~~図 fig-2
題: 索引の作り直しの手順
使う数字: 作る → 温める → 切り替える
~~~
"""  # 会話が書く中身のファイル(短くした例)。


@dataclass(frozen=True)  # 発行した依頼を書き換えない型にする。
class DrawnFigure(Effect):  # 「この図の、描き終えたSVGが欲しい」という依頼。
    figure_id: str  # 図の指定のid。


@do  # 呼ぶと、ページを組む手順(Program)ができる。
def build(content):  # 中身のファイルから、ページの本文と図の数を作る。
    page, drawn, specs = content, 0, FIGURE.findall(content)  # 組む本文・入った図の数・図の指定。
    for match in FIGURE.finditer(content):  # 図の指定ごとに、
        svg = yield DrawnFigure(match.group(1))  # 描き終えた図を依頼する。まだならNoneが返る。
        drawn += svg is not None  # 入った図を数える。
        box = svg or f"(図 {match.group(1)} を作成中。文章と表は先に読めます)\n"  # 無い図は、作成中の枠にする。
        page = page.replace(match.group(0), box)  # 図の指定を、図か枠に置き換える。
    return page, drawn, len(specs)  # 本文・入った図の数・図の指定の数。


@handler  # Programに取り付けられるハンドラにする。
@do  # ハンドラもyieldで、再開や委譲を指示する。
def not_yet(effect, k):  # 描いた図がまだ無い時の答え。
    if isinstance(effect, DrawnFigure):  # 図の依頼には、
        return (yield Resume(k, None))  # 「まだ無い」を返す。
    return (yield Pass(effect, k))  # 担当外の依頼は、外側のハンドラへ渡す。


def drawn_in(figures):  # 描き終えた図の辞書から、ハンドラを作る。
    @handler  # Programに取り付けられるハンドラにする。
    @do  # ハンドラもyieldで、再開や委譲を指示する。
    def answer(effect, k):  # 描き終えた図だけに答える。
        if isinstance(effect, DrawnFigure) and effect.figure_id in figures:  # 描き終えた図なら、
            return (yield Resume(k, figures[effect.figure_id]))  # そのSVGを返す。
        return (yield Pass(effect, k))  # まだの図は、外側のハンドラへ渡す。

    return answer  # 作ったハンドラを返す。


_, drawn, total = run(with_handlers([not_yet], build(CONTENT)))  # 図がまだ1つも無い時に組む。
print(f"図 {drawn}/{total}")  # 「図 0/2」と表示される。
_, drawn, total = run(with_handlers([not_yet, drawn_in({"fig-1": "<svg>…</svg>\n"})], build(CONTENT)))  # 1つ描けた時。
print(f"図 {drawn}/{total}")  # 「図 1/2」と表示される。
```

表示は「図 0/2」と「図 1/2」の2行です。

- `build`は、図の指定ごとに`DrawnFigure`を外側へ依頼します。図が在るかどうかは知りません。
- `not_yet`は、どの図にも「まだ無い」と答えます。`build`は作成中の枠を置き、文章だけのページを組みます。
- `drawn_in`は、描き終えた図にだけ答えます。まだの図は`Pass`で、外側の`not_yet`へ渡します。

コードの語を、先に整理します。

- `@do`を付けた関数は、呼ぶと実行の手順(`Program`)を返します。
- `yield DrawnFigure(...)`のような外側への依頼を、エフェクトと呼びます。依頼に答える部品がハンドラです。
- ハンドラは、届いた依頼`effect`と、止まった処理の続き`k`を受け取ります。
- `Resume(k, 値)`で値を渡して続きを動かし、担当外は`Pass(effect, k)`で外側へ渡します。
- `with_handlers`の並びは、先頭が外側です。

要は、ページがいつでも組めることです。図が1つも無くても、文章と表は先に読めます。作業役が図を描き終えるたびに組み直せば、描けた図から入っていきます。

## 全体の図 — 1つの頼みを、3つの役に分ける

*左が前の形、右が今の形です。中身は話していた会話が書き、見た目は雛形が持ち、図だけを作業役に頼みます。*

| 役 | 前の持ち主 | 今の持ち主 |
| --- | --- | --- |
| 中身(文・表・数字) | 作業役が、コードとissueを調べ直して書く | 話していた会話が、知っている事だけを書く |
| HTMLと見た目 | 作業役が、頼むたびに書く | スクリプトと、決まった雛形 |
| 図 | 作業役が、ページと一緒に作る | 別の作業役が、図の指定だけを読んで描く |

2026年10月1日の試しでは、この分け方で5分36秒かかりました。内訳は、会話が中身を書くのに57秒、作業役の起動に21秒です。作業役が図4つと見た目を作ってページを開くのに、4分18秒でした。試しの見た目は、後から決まった雛形にしました。

前の形の42分のうち37.2分は、調べ直し・スクリーンショット・放置でした。今の形では、中身を書く会話が既に文脈を持っています。見た目は雛形が持ち、確かめは1行の出力で済みます。

## 中身は、話していた会話が書く

報告の中身を一番よく知っているのは、その事を話していた会話です。別の作業役に頼むと、作業役は同じ事を一から調べ直します。前の形の15.7分は、この調べ直しでした。

そこで、中身のファイルは会話が書きます。形は次のとおりです。

| 節 | 書く物 |
| --- | --- |
| 題と冒頭 | 題と、何の報告かを言う短い文(1文は60字まで) |
| 結論 | 1〜3行の箇条書き |
| 語の説明 | 読み手の知らない語を、1行ずつ |
| 本文 | 箇条書き・表・図の指定(散文の段落は少なく) |
| まだ分かっていないこと | 箇条書き |

読み手は、その会話を読んでいなかった人です。この1ページだけで、何の話で今どうなっているかが分かるように書きます。流れ・因果・時間の順は、文で書かずに図の指定にします。

図の指定は、囲みの中に4行で書きます。

- 題:図の下に出る1行
- 見せること:何を見せる図か
- 使う数字:図に載せる数字と言葉の全部
- 形:例えば「左から右へ3つの箱と矢印」

図に載る数字は、「使う数字」に書いた物だけです。作業役に数字を探させないので、会話の知らない数が図に紛れ込みません。

## HTMLは、決まった雛形とスクリプトが組む

ページの見た目は、毎回AIに書かせません。見出し・表・図の枠の様式は、決まった雛形(殻)が持ちます。スクリプトは、中身のmarkdownを殻に入れるだけです。

筆者のスクリプトは、見た目をAIに書かせないので、1回組むのに4〜5秒です(2026年10月18日に3回測りました)。図の所は「図を作成中」の枠になり、作業役が描き終えたら組み直します。図は`figures/<id>.svg`という別のファイルなので、文章を直して組み直しても消えません。

本物のスクリプトは、doeffを使っていません。中身の読み取りと検査を純粋な関数にし、ファイル・時刻・ブラウザの入出力を1つの型の裏に閉じています。冒頭のコードは、同じ分け方をdoeffの依頼とハンドラで書き直した物です。

![同じbuildを、ハンドラの組を替えて組み直す](/images/zenn-use-cases-v0/generated/reports-flow.png)
*先に`not_yet`だけで組み、文章と表を開きます。作業役が図を置いたら、`from_dir`を足した組で組み直します。*

本番では、`drawn_in`の辞書の代わりに、`figures/<id>.svg`を読むハンドラを使います。ファイルが無ければ`Pass`で`not_yet`へ渡す形は、冒頭のコードと同じです。完全な例の`from_dir`が、このハンドラです。

## 図だけを、別の作業役に頼む

文章と表が開いたら、会話は図だけをサブエージェントに頼みます。依頼文は、毎回同じ決まった文にします。完全な例の`request`の命令は、次の文を出します。ここでは、パスを短くしました。

```text
中身のファイル: search-slow/content.md
このファイルの図の指定(~~~図 <id> の囲み)ごとに、SVGを1つずつ描いてください。
- 材料は、この中身のファイルだけです。コード・issue・会話の記録を調べ直しません。
- 数字と文を足しません。図に載せるのは、図の指定と中身のファイルにある物だけです。
- 図は search-slow/figures/<id>.svg に、viewBoxを付けた<svg>要素1つで保存します。
- 外のファイル・フォント・画像・スクリプトを読みません。
- 全部を保存したら、次の命令を1回実行します: uv run --no-project --with doeff==0.7.0 python report_page.py build search-slow/content.md
- 最後の行が「図 n/n」なら終わりです。ページ全体のスクリーンショットは撮りません。
- 返事は、描いた図のidと、何を見せたかを1行ずつ書きます。
```

依頼文の決まりは、前の形で時間が消えた所への答えです。

- 調べ直しをさせません。材料は中身のファイルだけです。
- 数字を作らせません。図の数字は、会話が図の指定に書いた物だけです。
- スクリーンショットで確かめさせません。組み直しの最後の1行で、図が全部入ったかが分かります。

図を描く作業役には、Opusを選びました。筆者の環境では、図と見た目の出来がOpusで良かったからです。Claude Codeでは、サブエージェントの定義の`model`でモデルを選べます。

完全な例でも、2026年10月18日に1回試しました。例の中身のまま、Opusのサブエージェントにこの依頼文を渡しました。作業役は図2つを描いて組み直し、頼んでから「図 2/2」になるまで90秒でした。

![完全な例で組んだページ](/images/zenn-use-cases-v0/generated/reports-page.png)
*完全な例の`build`が組んだページです。表は会話が書いた中身から組み、2つの図は作業役がSVGで描きました。*

## 手順を、Claude CodeのSkillにする

筆者は、この手順をClaude CodeのSkillにしました。報告や説明の資料を頼まれた時に、会話がSkillを読み、同じ順で進めます。短くすると、次の形です。

```markdown
---
name: report-page
description: 報告や説明の資料(図つきのHTML 1ページ)を頼まれた時に使う。中身は会話が書き、HTMLはスクリプトが組み、図だけをサブエージェントが描く。
---

# 図つきの報告を、1ページで出す

1. 頼まれたらすぐ、`report_page.py new <名>`を実行する(頼まれた時刻が記録に残る)。
2. `<名>/content.md`を書く。会話で分かっている事だけを書き、調べ直さない。
3. `report_page.py build <名>/content.md`で、文章と表を先にページにする。
4. `report_page.py request <名>/content.md`の出力を、そのままOpusのサブエージェントへの依頼にする。
5. 頼んだ人には「文章と表ができた。図は数分で入る」とだけ伝える。

- HTMLとCSSを手で書かない。見た目は雛形が持つ。
- ページ全体のスクリーンショットを撮らない。確かめは、buildの最後の行「図 n/m」で済ませる。
```

Skillの`description`は、Claude Codeがいつ読むかを決める1文です。「報告や説明の資料を頼まれた時」と場面で書くと、頼むたびに同じ手順に乗ります。

## 組む前に、中身を機械で確かめる

ページ全体のスクリーンショットをやめた代わりに、組む前に中身の決まりを機械で確かめます。決まりの外なら、ページを組まずに直す所を返します。

```python
@dataclass(frozen=True)  # 発行した依頼を書き換えない型にする。
class Record(Effect):  # 「所要の記録に1行を足したい」という依頼。
    event: str  # 出来事(requestedかopened)。
    drawn: int  # 入った図の数。
    total: int  # 図の指定の数。


def problems(content):  # 組む前に、中身のファイルの決まりを確かめる。
    checks = (  # 確かめる事と、当たった時の文。
        ("(ここに書く" in content, "雛形の「(ここに書く」が残っています"),  # 書きかけを止める。
        (FIGURE.search(content) is None, "図の指定が1つもありません"),  # 流れや比べを、文だけで書いている。
    )
    opening = content.split("\n## ", 1)[0]  # 最初の見出しまでの冒頭。
    long = [sentence for sentence in re.findall(r"[^。\n]+。", opening) if len(sentence) > 60]  # 60字を越える文。
    return [text for hit, text in checks if hit] + [f"冒頭の文が{len(s)}字です: {s[:12]}…" for s in long]  # 空なら組んでよい。


@do  # 呼ぶと、確かめてから組む手順(Program)ができる。
def checked_build(content):  # 決まりの外なら組まず、組んだら記録する。
    found = problems(content)  # 先に、中身の決まりを確かめる。
    if found:  # 決まりの外なら、
        return found  # 組まずに、直す所を返す。
    page, drawn, total = yield build(content)  # 冒頭のbuildで組む。
    yield Record("opened", drawn, total)  # 開いた事と図の数を、記録に足す。
    return page, drawn, total  # 組んだ本文と図の数を返す。


@handler  # Programに取り付けられるハンドラにする。
@do  # ハンドラもyieldで、再開や委譲を指示する。
def printed(effect, k):  # 記録の依頼を、表示で答える(本物はファイルに時刻つきで足す)。
    if isinstance(effect, Record):  # 記録の依頼には、
        print(effect)  # 何を記録するかを表示し、
        return (yield Resume(k, None))  # 処理の続きを動かす。
    return (yield Pass(effect, k))  # 担当外の依頼は、外側のハンドラへ渡す。


draft = CONTENT.replace("決めてほしい", "(ここに書く")  # 雛形の印を残した、書きかけの中身。
print(run(with_handlers([not_yet, printed], checked_build(draft))))  # 直す所の一覧を表示する。
run(with_handlers([not_yet, printed], checked_build(CONTENT)))  # 記録の依頼を表示する。
```

表示は次の2行です。

- `['雛形の「(ここに書く」が残っています']`:書きかけなので、組みません。
- `Record(event='opened', drawn=0, total=2)`:組めたので、開いた事を記録に足します。

`checked_build`は、冒頭の`build`を`yield`で呼びます。`@do`の処理どうしは、こうしてつなげます。本番の記録のハンドラは、依頼に今の時刻を付け、1行のJSONとしてファイルに足します。時刻を読むのは、ハンドラだけです。

筆者のスクリプトの検査は、もう少し多くを見ます。冒頭と本文の形は、別の検査の道具に確かめさせています。一部の項目は、文を読む判定器が確率で判じます。

| 検査 | 当たった時 |
| --- | --- |
| 雛形の印が残っている・図の指定が1つも無い | 組まない |
| 冒頭の1文が60字を越える・冒頭にidや括弧を置く | 組まず、当たった文と直し方を返す |
| 名詞を「・」で4つ以上並べる | 同じ |
| 散文の段落が1つの節に3つ以上・1段落が3文以上 | 同じ |
| 図のSVGが、外のファイルやスクリプトを読む | 組まない |

## 毎日使った1週間の数字

試しの後、この作り方を毎日使いました。筆者の作業機の1台に、2026年10月12〜18日の記録が253ページ分残っていました。スクリプトは、頼まれた時刻と、組むたびの時刻と図の数を記録します。

| 測った物 | 中央値 | ページの数 |
| --- | --- | --- |
| 頼まれてから、文章と表が開くまで | 3.4分 | 228 |
| 頼まれてから、図が全部入るまで | 9.2分 | 180 |
| 文章を先に開いたページで、開いてから図が揃うまで | 4.7分 | 125 |

![図の数ごとの、図が全部入るまでの分](/images/zenn-use-cases-v0/generated/reports-minutes.png)
*2026年10月12〜18日の180ページの中央値です。図が多いほど延び、試しの5分36秒(図4つ)より遅いページが多くありました。*

- 文章と表は、228ページの60%が5分以内に開きました。
- 図が全部入るまでは、図1つのページで2.8分、図4つのページで21.8分でした。
- 図が全部入るまで6分を切ったのは、180ページの36%です。試しの5分36秒は、毎日の中央値ではありません。
- 図の数は、図の指定が在る180ページで数えました。一度も開いた記録の無いページが25あり、訳は記録に残っていません。

## うまくいかなかったこと

- 図が多いほど、揃うまでが延びました。依頼は、1つの作業役に全部の図を描かせる形です。図ごとに作業役を分けて並べる形は、まだ試していません。
- 試しの4分18秒(図4つ)は、毎日の値よりずっと速い値でした。記録に作業役の起動と終わりの時刻が無く、訳を分けられていません。
- 180ページのうち55ページは、最初に組んだ時に図が既に入っていました。文章を先に開く手順を飛ばしたページです。
- 見た目を共通の雛形に任せたので、筆者のページはその雛形を置いた画面の中でしか描けません。ファイルを手元で開いても、本文は出ません。

## まとめ

- 報告のページを丸ごと作業役に任せると、調べ直し・スクリーンショット・放置で時間が消えます。
- 中身は、文脈を持つ会話が書きます。図の場所には、数字を書き切った図の指定を置きます。
- HTMLと見た目は、決まった雛形とスクリプトが持ちます。図が無くても、文章と表は先に開きます。
- 図だけを、決まった依頼文で作業役に頼みます。確かめは「図 n/m」の1行で済ませます。
- doeffでは、図を依頼にし、まだの図には外側のハンドラが作成中の枠で答えます。
- 試しは5分36秒、毎日の中央値は図が揃うまで9.2分でした。図の数で延びる所が、次に直す所です。
