## doeffとは？

[doeff](https://github.com/proboscis/doeff)は、**「何をするか」と「どう実行するか」を分けて書ける、Pythonのエフェクトとハンドラのライブラリ**です。

処理本体は必要な操作を`yield`で依頼します。その依頼をどう扱い、どんな値を返し、いつ処理を再開するかは、外側に取り付けるハンドラが決めます。

まずは、名前を依頼する処理と、その依頼に「花子」を返すハンドラを一緒に見てみます。最後の行でハンドラを取り付け、挨拶が返るところまで実行できます。

```python
from doeff import Pass, Resume, do, handler, run, with_handlers  # 依頼の委譲・再開・処理の定義と実行を使う。
from doeff_core_effects import Ask  # キーを指定して値を依頼するエフェクトを使う。

@do  # greet()を呼ぶと、実行する手順を表すProgramができる。
def greet():  # 名前の取得方法を決めずに、挨拶を組み立てる。
    name = yield Ask("name")  # 名前を依頼し、ハンドラから返された値を受け取る。
    return f"こんにちは、{name}さん"  # 受け取った名前を含む挨拶を返す。

@handler  # この処理をProgramに取り付けられるハンドラにする。
@do  # ハンドラ自身もyieldで再開や委譲を指示する。
def handle_ask_effect(effect, k):  # effectは届いた依頼、kは中断した処理の続き。
    if isinstance(effect, Ask) and effect.key == "name":  # 名前を求める依頼だけを担当する。
        return (yield Resume(k, "花子"))  # nameに「花子」を渡してgreetを再開する。
    return (yield Pass(effect, k))  # 担当外の依頼は、外側のハンドラへ渡す。

assert run(with_handlers([handle_ask_effect], greet())) == "こんにちは、花子さん"  # 取り付けて実行し、挨拶を確認する。
```

**`yield Ask("name")`と`yield Resume(k, "花子")`が対になっています。** 前者で名前を依頼し、後者で「花子」を渡して処理を再開します。その値が`name`に入り、次の`return`で挨拶になります。

`k`は、その依頼を出して中断した処理の続きで、**継続**と呼びます。`Resume`は、その続きを指定した値で再開する指示です。`Pass`は、担当しない依頼を別のハンドラへ任せる指示です。

- **エフェクト**：`Ask("name")`のような、外側に依頼する操作。
- **ハンドラ**：`handle_ask_effect`のような、依頼を受け取り、値や再開方法を決める処理。
- **`@do`と`yield`**：普通のPythonの制御構文の中で、これらの操作や別の計算をつなぐ書き方。

最後の行は、`greet()`で手順を作る→`with_handlers([handle_ask_effect], ...)`でハンドラを取り付ける→`run(...)`で実行する、という順です。`greet`には、名前を設定から読むか、テスト用の値にするかを書いていません。その選択をハンドラへ委ねています。

## ハンドラを替えると、同じ処理の動きが変わる

今度は「太郎」を返すハンドラを定義します。上のコードに続けて実行してください。`greet`の定義を変える必要はありません。

```python
@handler  # 同じエフェクトを別の方法で扱うハンドラを作る。
@do  # 再開と委譲を、最初のハンドラと同じ書き方で指示する。
def handle_test_ask_effect(effect, k):  # 依頼の型と再開する値の契約を保つ。
    if isinstance(effect, Ask) and effect.key == "name":  # 同じ名前の依頼を受け取る。
        return (yield Resume(k, "太郎"))  # 今度はnameへ「太郎」を渡す。
    return (yield Pass(effect, k))  # 担当外の依頼は外側へ渡す。

assert run(with_handlers([handle_test_ask_effect], greet())) == "こんにちは、太郎さん"  # 本体を変えず、ハンドラ交換で結果が変わる。
```

この例で変えたのは、ハンドラが供給する名前だけです。設定を読む、入力を待つ、といった取得方法もこの場所へ実装できます。doeffには値の供給や時間の制御などの標準ハンドラもあります。まずは、**依頼する処理と、その依頼を扱う処理を別々に書ける**ことが基本です。

## 操作を一度切り出せば、解釈を選び直せる

**エフェクトをどう解釈するかは、ハンドラ次第。** doeffはさまざまなハンドラを提供していますが、自作のハンドラも取り付けられます。

たとえば同じ「入力を待つ」という操作を、画面からの入力、別のイベント基盤、テスト用の入力列で実現する。操作の契約を保てば、呼び出し側の手順を維持したまま、外側のハンドラを入れ替えられます。必要な接続処理をハンドラに実装することで、新しいフレームワークも接続先にできます。

![同じAskに、ハンドラが違う名前を返す](/images/zenn-use-cases-v0/generated/main-concept.png)

同じ`greet`から作った2つの計算へ、それぞれ名前を供給します。`Ask`から文字列を受け取る契約を保ち、本体を変えずに結果を変えています。

テストでは、ネットワークや実ユーザーの入力に依存せず、操作を受け取って決めた結果を返せます。どの操作が依頼されたかも確かめられます。**処理本体と実行基盤の間に、差し替えられる境界を持てる**ことが、さまざまな用途をつなぐ土台です。

もちろん、エフェクトとして切り出さず本体から直接呼んだSDKは、この差し替えの対象になりません。ハンドラ側には、操作の意味に加えて、必要なキャンセル・例外・実行順の契約を実現する責任があります。

→ [エフェクトは何を切り出すのか — 副作用からドメインAPIまで](doeff-boundaries.md)

ハンドラは入れ替えるだけでなく、複数を重ねられます。名前の供給、ログ、失敗時の扱いを別々に受け持たせ、担当しない操作を外側のハンドラへ渡します。順番や処理する範囲によって意味が変わるため、その組み立て方を独立した記事で説明します。

→ [ハンドラはどう合成できるのか](doeff-handlers.md)

## 一つの書き方で、いろいろな困りごとに

`yield`で「してほしい操作」を渡し、ハンドラが結果を返したり、続きを動かすタイミングを決めたりします。

「なぜ`yield`なのか」が気になったら、[asyncioも`yield from`から始まった話](doeff-color.md)へ。中断して外側へ渡し、結果とともに再開する仕組みを入口に説明します。

coroutineとの比較は、[coroutineとエフェクト・ハンドラは何が違うのか](doeff-coroutines.md)へ。Pythonの`async def`・`await`とdoeffの`@do`・`yield`で、何を外側へ渡し、誰が続きを動かすのかをコードで比べます。

この分離を、依存の供給、状態管理、失敗の扱い、並行処理、保存済みの結果の再利用にも使えます。さらに、LLM・画像生成・エージェント・イベント・外部操作のパッケージが、具体的な用途を同じ計算へつなぎます。

## 処理の流れ

![Askを受け取り、値を渡して挨拶の続きを再開する](/images/zenn-use-cases-v0/generated/main-flow.png)

`yield Ask("name")`で本文が中断し、ハンドラが「花子」を渡すと、その値が`name`に入って次の行へ進みます。最後の`return`が、`run()`の結果になります。

doeffはPythonのジェネレータとRust製VMを組み合わせて、この受け渡しを実行します。VMがエフェクトをハンドラへ渡し、ハンドラの指示に従って「ここから先の処理」を再開します。この続きが**継続**です。内部の命令とPythonのコードがどう対応するのかは、別の記事で追えます。

## ばらばらの便利機能を、同じ処理で組み合わせる

DIだけなら、関数の引数でもできます。非同期処理だけなら、`asyncio`で十分なこともあります。

doeffの面白さは、これらが共通の計算形式に乗ることです。たとえば、対局の入力をLLMに判断させ、イベントとしてゲームへ渡し、結果を観測する。あるいは、エージェントの仕事を並行に進め、差分を確認して通知する。個々の操作を同じ計算としてつなぎ、必要な場所に仮想時間や結果の再利用を組み合わせられます。

**入口は別でも、学んだ書き方がほかの用途へつながる。** だから、最初から全部を使う必要はありません。

## 使う範囲は選べる

純粋な計算は普通のPythonのままで構いません。ハンドラの順番や状態の範囲には意味があり、あらゆる組み合わせが自動的に正しくなるわけでもありません。

実行方法を変える必要がある処理を一つ選んで、小さく試す。それで十分です。

共通の`@do`で処理を組み立て、ハンドラで動かし方を選ぶ。詳しくは、上の中から気になる入口へ進んでみてください。
