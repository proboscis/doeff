doeff-hy-check: 保存から引けない依存の展開を、import の段ごとに子の process で並べる(agora-redesign #3869 の (b))

検める file が import する .hy を 1 本の thread で 1 file ずつ展開していた。import の段の中の file は互いの展開を使わない
(agora-controllers の 3 file で段は 5〜7 つ・最も広い段は 126 file)ので、project_closure を段ごとに回し:
- 段の中で保存から引ける file は親で引く。引けない file が 2 つ以上の段だけ、子の process の pool(forkserver・数 =
  min(EXPANDER_LIMIT 8, この process が使える CPU の数))に渡す。1 つなら親で展開する。
- pool は初めて要る時に起こし、1 回の実行の中で段をまたいで使い回す。全部引ける実行では起こさない。
- 保存への書きは親の 1 か所(_kept)。子は書かない。
- 子が答えを返さずに落ちたら、答えの無い file を名指す ExpansionWorkerLostError(RuntimeError の下 — main は exit 2)。
展開の文の gensym の名は前の commit で file の中の順に振り直してあるので、並べても直列と同じ文になる。
