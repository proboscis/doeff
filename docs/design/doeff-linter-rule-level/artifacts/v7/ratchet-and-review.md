## 5. ratchet の設計(決定 A の実装の形)

### 5.1 ratchet とは

「critical の集合が増えない」ことを、マージの前に機械で確かめる検査です。今の 873 件(Jev 以外)は残っていてよく、**新しい critical を 1 件も入れない**ことと、**減らし始める**ことが目標です。件数の比較ではなくキー(file・規則・定義の名)の集合の包含で見ます — 3 件直して 1 件足す commit は赤です。

### 5.2 Q1 — 基点をどう持つか

| | 今の一覧(通すため) | 案 L: 一覧を残し「減るだけの基点」にする | 案 M: 一覧を持たず main と比べる(推奨) |
|---|---|---|---|
| 載った違反の見え方 | warning に下げる(critical と数えない) | critical のまま数える・見せる | 同じ |
| 増える | 新しい規則を入れる時に dir が増える。止めるのは hook だけ | 「増えていない」をマージ前の検査でも止める。増えてよいのは新しい規則を入れる 1 回だけ(issue に記録) | 自動(基点 = main。直せば減り、足せば赤) |
| 減る | 直した人が file を消す(消し忘れが残る — 今も deploy の 2 件が当たりが無いのに残っている) | 直したら自動で消える(当たりの無い項目は赤) | 自動 |
| 持ち物 | file 1361 本 | 同じ file(減るだけ) | 無し(検査の時に main でも linter を実行。6 秒) |
| 弱点 | 名前で覆うので、載った定義の中身を書き換えても載ったまま | 同じ | 同じ(名前で比べるため) |
| 良い点 | — | 1 件ずつ理由を書いた「見える負債の一覧」になる | file が無く、conflict も消し忘れも無い |

図 3(元の mermaid = `fig/fig3-ratchet-with-list.mmd`)

案 L を採るなら条件は 4 つ: 1. 載っていても critical として数える・見せる。2. マージ前の検査で「一覧が増えていない」も確かめる。3. 直したら自動で消える。4. 増えてよいのは新しい規則を入れる時の 1 回だけ。
