## 3. 設計 — 禁止の綴りを列挙せず、運ぶ名の閉包を名簿と突き合わせる

**素朴な直し方(採らない)**: `setv` / `setx` / `let` / `<-` …を列挙して、どれかが当たれば赤。
⇒ これは同じ病そのもの。列に無い 7 番目の綴りで素通りする。

**採る形(逆向き)**: 「何が禁止か」を列挙せず、**「何が許されているか」を 1 か所に宣言**して、
実測の集合と突き合わせる。

```
                     ┌─ hy.read-many(Hy 自身の reader)
file(judgment.hy / agentd.hy)
                     └─ form の木 ──┬─ (mail-turn-text-of …) の呼び
                                    │      └─ 呼びを包む form の頭 …… `<-` でなければ赤
                                    └─ 束ねた名 text ─┬─ 運ぶ名の閉包(2 版で足した)
                                                       │    (.append bodies text) → bodies も運ぶ名
                                                       │    (setv other text) / (<- other str text) → other も運ぶ名
                                                       └─ 閉包の全部の**読み**の集合
                                                              └─ 冊の名簿 MAIL-TURN-TEXT-CONSUMERS と一致しなければ赤
```

- 呼びを包む form が `<-` でない ⇒ 包んでいる・その場で組んでいる ⇒ 赤。
- **運ぶ名の閉包**(2 版): 束ねた名から始め、名簿の読み手が `(.m recv 文)` の形で受け手へ積んだら `recv` も、
  `(setv 名 文)` / `(<- 名 型 文)` で写したら `名` も運ぶ名。同じ頂点の form の中で不動点まで。
  由来 = 盲検 B(`blind-B.md`): 1 版は `text` の読みしか見なかったので、積んだ先 `bodies` を後から歩いて
  見出しを書き足す形が緑で通った。
- 閉包の全部の読みの頭の綴りを集め、名簿の鍵の集合と**一致**を見る。
  - 名簿の外の読み手が読んだ(`setv` / `+` / `let` の列 / `len` / `enumerate` / 別の関数へ渡す)⇒ 赤。
  - 名簿の読み手が読まなくなった(文を捨てた)⇒ 赤。
  - 運ぶ名ごとの**最初の書き込み**(導入・`(setv bodies [])`)だけは読みに数えない。束ねた名の導入は
    `<-` の form そのものなので最初から済み ⇒ 2 度目の書き込み `(setv text "fixed")`(読まずに置き換える)
    も赤(`overwrite`)。
- 名簿はこの冊の**唯一の宣言点**(他の 4 つの名簿と同じ節に置く)。読み手を足す便は
  名簿へ 1 行宣言すると緑になる。針は読み手の数も綴りも知らない。
- 名簿の値(2 版): `judgment.hy` = `bodies.append`(積む)+ `tuple`(積み終えた bodies をそのまま返す)/
  `agentd.hy` = `SessionInterject`(注入の要求へそのまま渡す)。

部品(冊の中・6 つ):

| 名 | 役 |
| --- | --- |
| `form-use-head` | form の頭の綴り(`(f …)` → `"f"`・`(.m recv …)` → `"recv.m"`・属性 → `"."`・列 → `"(列)"`) |
| `top-form-name-of` | 頂点の form の名(`#^ 型` の注記を剥がす) |

## 4. 覆う範囲(註にそのまま書く — ここが今回の失敗の再発を防ぐ 1 点)

註は「塞いだ」と書かず、**3 つの範囲を名指しで並べる**:

**赤にする範囲** = 同じ頂点の form の中で、運ぶ名を名簿の外の読み手が読む/書き直す形。

**赤にしない範囲**(この針は捕まえない):
- 別の頂点の form へ渡った後の組み替え
- `handlers.py` の実 I/O の中での組み替え
- `mail-turn-text-of` を呼ばずに文を作る形(これは「呼びは 1 つ」と法の挙動の反例が別に押さえる)

**過剰に赤くする範囲**(正当でも赤になる — **その時は検査を緩めず、名簿を人が 1 行直す**・依頼者 §5):
- 組み替えない読み(文の長さを測る `(len 文)` 等 — 盲検 A・`blind-A.md`)
- 積む先の名の改名(`bodies` → 別名は名簿の鍵 `"bodies.append"` と食い違う — `renamecarrier`)
- 読み手の追加(`newreader`)
- 直し方はどれも名簿へ 1 行(`lencheckdeclared` / `renamecarrierdeclared` / `newreaderdeclared` が緑で対を成す)。
  **数や範囲を書き換えて緑にする直しは禁止**(緩めて緑にすると、次の読み手が邪魔だからと針ごと消す)。

**form にすると同時に死ぬ族が 3 つ**(依頼者 §4・残り約 405 本を同じ形で畳む根拠):
1. 行の折れ方で素通り/誤検出する族(本題)
2. 註が「その綴りを避けた」と説明している行を使用として数える族 — Hy の reader は `;;` を捨てるので構造的に免れる(`commentmention` = 緑)
3. 文字列 literal の中の綴りを数える族 — String と Symbol は別の節点(`stringmention` = 緑)
