反例候補は、**緊急メールの見出しを、共通の合成関数を呼んだ後に `agentd.hy` が追加する実装**です。提案された構造検査では検出できないと予測します。ただし、再照準後の検査は未提示・未実装のため、通過を実測したものではありません。

1. **提案する実装**

   機能要求は「処理中に届いた緊急メールをモデルが見落とさないよう、優先度を明示する」です。材料2の distribution の変更例に対応します。

   `packages/doeff-agents/src/doeff_agents/sessionhost/acp/agentd.hy` の3502行付近で、既存の呼び出しと `SessionInterject` の間に追加します。

   ```hy
   (<- text str (mail-turn-text-of message-id message.spec body message.status))
   (when (= (.get message.spec "priority") "urgent")
     (setv text (+ "【優先度: 緊急】\n" text)))
   (<- outcome (| Interjected SessionRefused)
       (SessionInterject :session-id job.session-id :text text :ref message-id
                         :attachments carried))
   ```

   検査や共通関数は変更しません。通常のメールの挙動を保ちながら、割り込みを扱う場所に表示機能を足す、現実的な実装です。

2. **各検査が拒否しない理由**

   | 検査 | 通過を予測する理由 |
   |---|---|
   | (a) judgment のメール合成呼び出し | 変更しないため、呼び出し1個と必要な引数が残る。 |
   | (b) agentd のメール合成呼び出し | 既存の呼び出し1個と全引数がそのまま残る。`call-args-of` は、戻り値を後から加工していることを検査しない。 |
   | (c) 手番の env と添付の受け渡し | `headless-send-program` の呼び出しは変更しない。 |
   | (d) 関所の読み手の集合 | 関所の呼び出しも、それを囲む関数名も変更しない。 |
   | (e) resume の添付名簿 | `resume-params-of` は変更しない。 |
   | (f) drain の反映 | settings と control の処理は変更しない。 |
   | 字面検査の ratchet | 冊に検査を追加せず、既存の literal 検査も変更しない。 |
   | 提示された backend 禁止語の検査 | 追加コードに `BACKEND-HEADLESS` や `"headless"` はない。 |

   読み取った現行の対象 deftest にある挙動検査は、通常メール `"hello"` の launch/send を検証しており、この緊急割り込みの条件は通りません。他の検査については未確認です。

3. **侵している責務と公開契約**

   所有者は judgment の `mail-turn-text-of` です。その実コードの説明には、初回・send・割り込みが同じ文を運び、文を組む点はここだけとあります。

   追加コードによって、**優先度の解釈と見出しの組み立てを `agentd.hy` も所有**します。共通関数への依存は残っていますが、最終的な文の合成点は一つではなくなります。同じ緊急メールでも、通常入力と割り込みでモデルへ渡る文が異なります。

   「合成関数を呼ぶ」という必要条件では、「その関数だけが合成する」という契約を検査できない例です。

4. **再現手順と観測結果**

   設計担当が隔離した作業コピーで、次を確認できます。

   - 基準 commit に提案どおりの再照準を実装し、対象検査が緑になることを確認する。
   - 上記の追加だけを適用し、材料6のコマンドで対象の4 deftest と ratchet を個別に実行する。**予測：追加前と同じく緑。**
   - 同じ Message に `body="現在の処理状況を報告してください"`、`priority="urgent"` を設定する。
   - 通常入力では `message-bodies-of` の生成文、実行中の job への割り込みでは `SessionInterject.text` を記録して比較する。

   **予測する観測結果：割り込み側だけに `【優先度: 緊急】` が追加される。** 共通関数の呼び出しが残ったまま、送信文の判断が agentd に分散したことを確認できます。

5. **実測と未確認事項**

   - **確認済み：** ローカル HEAD は指定の基準 commit。上記の挿入位置、合成関数の責務説明、現行の対象 deftest を読み取りました。
   - **未実行：** ソース変更、検査、実行時の文比較。共有ソースは変更していません。
   - **前提：** 新しい `priority` 欄を Message が受け入れること。上流の schema が拒否する場合、その機能追加も必要です。
   - **不足：** 再照準後の検査本体、ratchet の実装、緊急メールに対する既存の挙動検査の有無。
   - **重要な区別：** 現行の検査は、既に4引数の呼び出しと古い literal が食い違っています。したがって「現行コマンドがこの差分で緑になる」とは主張しません。これは**提案された再照準後の検出範囲に対する反例候補**です。
