# 連載の各回を、公開計画の表に書いた刻にZennの予約公開で出す

- 決定日時：2026-10-21（JST）
- 置き場：連載全体の公開の仕組みの決定なので、連載の決定記録として置く。
- 決定担当：出し方(交互に毎日・始める日・AIが公開する)はユーザー。仕組みの形は、作業ボードのcard ki-d57dfc7273d4(答えに沿って、決めた日時に出す仕組み)を受け持ったAIの会話(Opus 5.5)。
- 根拠：
  - ユーザーの答え(連載の始め方の依頼書・2026-10-20 14:05〜14:06)。出し方は「2つを交互に毎日出して、毎日反応を確認して戦略を再検討する」、始める日は「今日から」、公開の操作は「AI が表の刻ごとに、その回を公開にして push する」。時刻は答えに無く、取り組みの持ち主が戻せる決めとして毎日8:00 JSTを置いた。
  - Zennの公式ガイド(https://zenn.dev/zenn/articles/zenn-cli-guide)の予約公開の節。front matterで`published`を`true`にし、`published_at`(日本時間の`YYYY-MM-DD hh:mm`)を未来に書いてpushすると、記事は公開予約の状態になり、刻を過ぎると自動で公開される。zenn-model 0.5.6の検査も「未来の`published_at`には`published: true`を書く。刻を過ぎるとZennが自動で公開する」と答える。
  - 刻ちょうどにpushする置き場が無い事(2026-10-21の調べ)。agoraの周期の仕事は専用のPod・CronJobを足さない決まり(ユーザー2026-10-09「never on dedicated pods!」)で、見回りの周期のjobはdoeffの書き出しの道具を走らせない。doeffのGitHub Actionsはpushの前例が無く、mainへ入れる列(land)に要求を出せない。会話を刻ごとに起こす鎖は1回きりで切れやすい。

## 決めた事

| 決めた事 | 訳 |
| --- | --- |
| 公開の刻は、公開計画の公開順の表の公開状態に「公開予定 YYYY-MM-DD hh:mm JST」で書く | 刻の定義元を表の1か所にする。順や刻の見直しは、表を直してmainに入れる事になる。見回りの段「閲覧の数」と`agora analytics measure`は公開状態を頭の語で読むので、刻を足しても読み方は変わらない |
| 刻を書いた回は、`zenn-content`に`published: true`と`published_at`の組で置き、Zennの予約公開で刻に出す | 刻ちょうどに動く物を新しく置かずに、刻に出る。刻にpushが遅れたり落ちたりする事が無い |
| `push_zenn_branch.py`の「publishedを変えない」決まりを、「読者に見えている記事は変えない・刻の前の記事は予約にだけ変えられる・その場では公開しない」に替える | 予約を置くには、刻の前の記事の`published`を`true`にする必要がある。公開済みの記事を非公開に戻さない守りと、刻の無い公開をしない守りは残す。読者に見えているかは、`published_at`と今(`--now`)で判じる |
| 予約の在る記事を表から外す書き出しは止める | Zennは記事の削除をダッシュボードからしか受けないので、branchから外しても予約は残り、刻に出てしまう |
| 刻の後に`record_published.py`で、ZennのURLが開ける回を「公開済み <URL> <刻>」に直す | 見回りの段「閲覧の数」は公開済みの回だけを数える。公開済みに直すと、他の回の本文のリンクもZennのURLになる。開けない回は直さず、終わりのcodeを1にして知らせる |
| 公開済みに直した回にも刻を残し、書き出しは同じ`published_at`を書き続ける | Zennは公開した記事の公開日時を後から変えない。公開済みの記事に未来の`published_at`を書いて非公開に戻った例がある(https://zenn.dev/sdb_blog/articles/zenn-publication-date-mistake)ので、値を変えない |
| 刻の前の回の本文へのリンクは、公開済みに直すまで張らない | 刻の前のURLはZennで404になる。刻の後に`record_published.py`を走らせるまでは、題に「(公開予定)」を添える今の形のまま |
| 残る15本を、10月21日から11月4日まで毎日8:00 JSTで予約する | ユーザーの答えの交互の順。AIエージェントの連載が10月31日の6本目で終わった後は、doeffの連載の7〜10本目を毎日1本出す |

## 確かめ方

`tests/test_zenn_reserved_publish.py`が、偽の時刻と偽のrepoで次を確かめる。

| 確かめる事 | 中身 |
| --- | --- |
| 表の読み | 刻の在る公開予定・刻の無い公開予定・刻の在る公開済みを読み分け、刻の書き損じを例外にする |
| 書き出し | 刻の在る公開予定は`published: true`と`published_at`、刻の無い公開予定は`published: false`で書く |
| 予約と公開の守り | 刻の前の予約を置く・刻を変える・予約を解くのは通し、見えている記事の変更・その場の公開・予約の置き去りは止める |
| 偽のrepoへのpush | 偽のremoteの`zenn-content`へ予約を置き、刻の後に同じ書き出しを送っても変わらず、刻を変える書き出しは止まる |
| 公開済みへの直し | 刻の前の回は直さず、刻の後でZennで開ける回だけを「公開済み <URL> <刻>」に直す |
| 今の公開計画 | 今の表の15本が、交互に毎日8:00 JSTで、答えの前に公開した1本目のほかは刻の前である |

## 戻す手順

予約を解くには、刻の前の回の公開状態から刻を消して「公開予定」に戻し、mainに入れて`push_zenn_branch.py`を走らせる(`published: false`に戻る)。仕組みそのものを戻すには、このcommitの前の版へ`render_release.py`・`export_zenn.py`・`push_zenn_branch.py`・公開計画を戻し、`record_published.py`と確かめを消す。刻を過ぎて出た回は戻せない(Zennの記事の非公開と削除はダッシュボードで行う)。
