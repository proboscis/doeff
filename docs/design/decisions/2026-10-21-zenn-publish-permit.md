- 決定担当：1本ずつ許可を得る決まりはユーザー。仕組みの形は、作業ボードのcard ki-d8609b0df9b8(許可の無い回を予約も公開もしない仕組み)を受け持ったAIの会話(Opus 5.5)。
- 根拠：
  - ユーザーの決定(2026-10-21)。doeffの記事の公開は1本ごとに内容の確認を要する。出したのは全体の計画の許可だけなので、Zennの記事などは1本ずつ順に依頼書で確かめる。連載の戦略と計画の合意は全体の計画の許可で、1本ずつの公開の許可ではない。
  - 同じ日に、持ち主が15本の予約の刻を外した(`zenn-content` 078948e6a)。1本目も取り下げ、16本とも`published: false`になった(`zenn-content` d1c12c51e)。
  - 公開計画の公開順の表は、agoraの見回りのjob(プログラムのreconcile — 周期のjob patrol)の段「閲覧の数」と`agora analytics measure`も読む。どちらも表の行を5つの欄の綴りで読み、公開状態を頭の語(公開済み・公開予定・下書き)で読む(agora-controllersの`controllers/shared/core/publication_plan.hy`)。

## 決めた事

| 決めた事 | 訳 |
| --- | --- |
| その1本の公開の許可を問うた依頼書のidを、公開状態の刻の後ろに「許可 lt-…」で書く | 許可を回の行に置き、表を読めばどの回に許可が在るかが分かる。欄を足すと、agoraの2つの読み手が表の行を1つも読めなくなる。公開状態の後ろに書けば、頭の語で読む読み手は変わらない |
| 書くのは、その回の本文と図を見せた依頼書1通に、利用者が許可と答えた後だけ | ユーザーの決定(1本ずつ順に依頼書で確かめる)。依頼書は1通に記事1本なので、idは回ごとに違う |
| `push_zenn_branch.py`は、許可の無い回を`published: true`(予約か公開)で書き出す時に止まり、何もpushしない | 手違いで表に刻を書いても、許可の無い回はZennに予約されない。止まると全部の回をpushしないので、許可の在る回だけが先に出る事も無い |
| 読者に見えている回は、許可が無くても今の決まり(公開を変えない)のまま保つ | 許可の決まりの前に出た回は、もう読者に見えている。許可が無い事で止めると、他の回の直しも出せなくなる |
| 許可の無い回の予約を解く(`published: false`に戻す)書き出しは止めない | 許可の無い予約がbranchに残った時に、刻の前に外せるようにする |
| 同じidを2つの回に書いた表と、「許可 lt-…」の形でない許可は、`render_release.py`が読まずに止まる | 別の記事の許可を流用しない。書き損じを「許可なし」と黙って読むと、許可の在る回が止まる訳が見えない |
| `record_published.py`が公開済みに直す時も、「許可 lt-…」を刻の後ろに残す | どの許可で出た回かを、出た後も表から辿れる |

## 確かめ方

`tests/test_zenn_reserved_publish.py`の「公開の許可」の節が、偽の時刻と偽のrepoで次を確かめる。

| 確かめる事 | 中身 |
| --- | --- |
| 表の読み | 刻と許可・許可だけ・刻だけの公開状態を読み分け、許可の書き損じ(形・語・順・字)と、1つのidを2本に書いた表を例外にする |
| 書き出し | 書き出す記事が行の許可を運び、`export_zenn.summary`に出る。許可はZennの記事のfront matterに入れない |
| 予約の守り | 許可の無い回の予約を置く・保つ・刻を変えるのは止め、同じ書き出しに許可を足すと通す。下書き・予約を解く・読者に見えている回は許可が無くても通す |
| 偽のrepoへのpush | 許可の無い回を1本でも含む書き出しは何もpushせず、許可の在る1本だけの予約は偽のremoteの`zenn-content`に届く |
| 公開済みへの直し | 公開済みに直した行に「許可 lt-…」が残る |
| 今の公開計画 | 公開の刻を書いた公開予定の回は、どれも許可を持つ |
