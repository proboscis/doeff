# 刻を過ぎた回を、毎日8:10 JSTに人の手なしで公開済みに直し、リンクだけを張り直す

- 決定日時：2026-10-22（JST）
- 置き場：連載全体の公開の仕組みの決定なので、連載の決定記録として置く。
- 決定担当：毎日の直しを置く事は、取り組みの持ち主(作業ボードのcard ki-9c84cc3b4e19の本文と、doeff-publishの持ち主の10-22の決定)。仕組みの形は、そのcardを受け持ったAIの会話(Opus 5.5)。
- 根拠：
  - 予約の刻を過ぎた回は、`record_published.py`で表を「公開済み <URL> <刻>」に直し、mainに入れて`push_zenn_branch.py`を走らせるまで、他の回からリンクされず、閲覧の数にも入らない([予約公開の決定記録](2026-10-21-zenn-reserved-publish.md))。これを走らせる物が無かった。
  - doeff-publishの持ち主の決定(10-22)。「刻を過ぎた回の表を毎日直す仕組みは最初の公開の前に要る」「この仕組みは表を直すだけで、公開も予約もしない」。公開は1本ごとの許可のまま([公開の許可の決定記録](2026-10-21-zenn-publish-permit.md))。
  - agoraの周期の仕事は、専用のPod・CronJobを足さず、既に在るdoeff-clusterのjobに載せる(ユーザーの決定 2026-10-09)。2026-10-22の時点で、新しい常駐のjobを置けるworkerの枠はどこにも無い。
  - 見回りのjob(プログラムのreconcile — agora-controllersの`controllers/patrol`)は子processを撃てないので、doeffの道具を走らせられない。agoraの担当の道具の組の同期のjob(agora-controllersの`agent-toolset-sync` — zeusのPodのworkerの上)は、日次の刈りと計器で既に機体の命令を撃っている。
  - マージの列の便は数十秒でmainに入る(10-20のL2643は登記から着地まで14秒)。

## 決めた事

| 決めた事 | 訳 |
| --- | --- |
| 直しの1回を`record_sweep.py`の1命令にする。1回は、刻を過ぎて開ける回を公開済みに直す段と、リンクを張り直す段の2つ | 走らせる側(agoraのjob)はdoeffの道具の中身を知らずに、1つのargvを撃つだけで済む。直しの規則の定義元は`record_published.py`の1か所のまま |
| agoraの同期のjobが、毎日8:10 JSTと起動の時に、doeffのmainの先端を取り寄せた持ち越しのclone(workerの作業の根の`state/publication-sweep/doeff`)でこの命令を撃つ。0で終わらなかった回の後は、10分後から続けるたびに倍(上限1時間)で撃ち直し、2回続けて0で終わらなければ健康の帯の項を赤にする | 予約の刻は8:00 JSTなので、8:10には読者に見えている。起動の時にも撃つのは、8:10にjobが入れ替わっていた日を取りこぼさないため(何度走らせても同じ所に落ち着く)。cloneを持ち越すと、2回目からの取り寄せは数秒で済む(初回は約50秒)。1回の一時の詰まりでは見回りの会話を起こさない |
| 直した表は、表だけのcommitにして`wt/zenn-record-sweep`へpushし、マージの列に載せる。知らせの宛先は取り組みdoeff-publishの持ち主の会話 | mainへ直にpushしない。main入りの結末と失敗は持ち主に届く |
| 同じbranchの前の便が列に在れば、main入りを待つ秒まで待つ。入ればmainの先端から直しを続け、待っても残れば直さない(終わりのcodeは1) | 同じ直しを2度載せない。便は普通は数十秒で入るので、待っても列に残る便は詰まりとして知らせる |
| main入りを待つ秒(既定600秒・agoraのjobは300秒を渡す)まで待ち、入ったらmainの先端から書き出してリンクを張り直す。入らなければ作業木を直す前の木へ戻し、リンクは張らずに終わりのcodeを1にする | 便は数十秒で入るので、普通は同じ1回でリンクまで張れる。入らない便は詰まりなので、知らせて人かAIの会話が見る |
| リンクを張り直すのは、mainの表で公開済みの回のうち、`zenn-content`の他の回の本文がまだそのZennのURLを含まない回が在る時だけ。リンクが揃っている日は、mainと`zenn-content`の本文が違っても送らない | 張り直しの書き出しは、公開済みの回の本文の直しも一緒に送る。揃っている日にも送ると、mainに入った本文の直しが毎日人の手なしに読者に出る。カードの「表に変わりがあればpush_zenn_branch.pyを走らせる」の範囲に留める。要否を`zenn-content`の中身で決めるので、前の回が待ちを越えて諦めた便が後でmainに入った時と、会話が手で直した時も、次の回が張り直す |
| リンクの張り直しは`push_zenn_branch.py --keep-schedule`で送る。予約と公開の設定(`published`と`published_at`)を変える記事が1本でもあれば、何もpushしない | この仕組みは予約も公開もしない。許可を得た回の予約は、その許可を得た会話が置き、その時にリンクも一緒に送られる |
| 8:10の直しは、見回りのjob(プログラムのreconcile)の段「閲覧の数」が9時にmainの表を読む前にmainに入る | 閲覧の数は表で公開済みの回だけを数える。8:10の後の便の待ちは数十秒なので、50分の間がある |
| 刻を過ぎたのにZennで開けない回・前の便が待っても列に残る時・便がmainに入らない時・張り直しが止まった時は、終わりのcodeを1にする | 同期のjobが健康の帯の項を赤にし、見回りのjob(プログラムのreconcile)の検査が見回りの会話へ知らせる |

## 確かめ方

`tests/test_zenn_record_sweep.py`が、偽の時刻・偽のrepo(本物の公開計画と原稿と画像を写した一時のrepoと、remoteに見立てたbare repo)・偽のagora・偽のZennで次を確かめる。

| 確かめる事 | 中身 |
| --- | --- |
| 予約と公開の設定を変えない書き出し | 本文だけの違いと新しい下書きは通し、予約を置く・解く・刻を変える・予約の在る新しい記事は名指す |
| 刻の前 | 列に載せず、mainもzenn-contentも変えない |
| 刻の後で開ける回 | 表を公開済みに直したcommitが、知らせの宛先を名乗って列に載り、mainに入り、2本目の本文の1本目へのリンクがZennのURLになる。どの記事の予約と公開の設定も変わらない。2回目は何も変えない |
| 列に前の便が残る時 | 待っても残れば直さず、終わりのcodeが1 |
| 列の前の便が待つ間にmainに入った時 | 作業木をmainの先端へ進め、同じ直しを2度載せず、リンクだけを張り直す |
| 前の回が諦めた便が後でmainに入っていた時 | 次の回がリンクを張り直す |
| リンクを張り直した後 | mainに本文の直しが入っても、次の回は送らない |
| 直す回の無い日(公開済みの回が無い) | mainに本文の直しが在っても、zenn-contentへ送らない |
| 刻の後で開けない回 | 終わりのcodeが1で、列に載せない |
| 便が入らない・断られた時 | 作業木を直す前の木へ戻し、リンクを張らず、終わりのcodeが1 |
| 許可を得た回の予約がmainにだけ在る時 | 1本目の直しはmainに入るが、zenn-contentへ予約を送らない |
