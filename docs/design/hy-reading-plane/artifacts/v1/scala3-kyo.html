Scala 3 + Kyo (+ ScalaPy) で effect を使うとどう見えるか

左 = 今の Hy(agora-controllers の実物: controllers/messaging/…/conversation_input.hy)。右 = 同じ物を Scala 3 + Kyo で書いた形。 Kyo の要は A < S(「A を返す計算で、effect S がまだ解かれていない」)。effect は型の交わり ReadInput & WriteInput で並び、 handler を当てるたびに型から消え、A < Any になったら .eval で値を取り出せます。doeff の <- は Kyo の直接形(defer { … .now })に 1 対 1 で写ります。
⚠ Kyo の名は版で動きます(IO → Sync など)。ここに書いた形は Kyo 0.x の骨で、細部は実験の時に版へ合わせます。

1. effect の定義 defeffect → ArrowEffect

今の Hy(intent/conversation_input.hy:176)

(defeffect ReadInput
"入力の行を id で 1 つ読む(答え = 頭の註)。"
{:fields [(: id str)]
:answer (| InputRow InputAbsent InputUnreadable)
:tags {:context "messaging" :role "intent"}})
(defeffect WriteInput
"入力の行への書き 1 つ(答え = 頭の註)。"
{:fields [(: write InputWrite)]
:answer WriteAnswer
:tags {:context "messaging" :role "intent"}})

Scala 3 + Kyo

import kyo.*
/** ReadInput の答え(Scala 3 の union 型 — Hy の (| …) と同じ形) */
type ReadAnswer = InputRow | InputAbsent | InputUnreadable
/** 入力の行を id で 1 つ読む(答え = 頭の註)。 */
@context("messaging") @role("intent")
sealed trait ReadInput extends ArrowEffect[Const[String], Const[ReadAnswer]]
object ReadInput:
// effect を呼ぶ側の口: 答えは ReadAnswer、型には ReadInput が残る
def apply(id: String): ReadAnswer < ReadInput =
ArrowEffect.suspend[Any](Tag[ReadInput], id)
// handler を当てる側の口: f が答えを作り、型から ReadInput が消える
def run[A, S](f: String => ReadAnswer < S)(v: A < (ReadInput & S)): A < S =
ArrowEffect.handle(Tag[ReadInput], v)([C] => (id, resume) => f(id).map(resume))
sealed trait WriteInput extends ArrowEffect[Const[InputWrite], Const[WriteAnswer]]
object WriteInput:
def apply(w: InputWrite): WriteAnswer < WriteInput = ArrowEffect.suspend[Any](Tag[WriteInput], w)
def run[A, S](f: InputWrite => WriteAnswer < S)(v: A < (WriteInput & S)): A < S =
ArrowEffect.handle(Tag[WriteInput], v)([C] => (w, resume) => f(w).map(resume))
1 effect につき「呼ぶ口」と「handler を当てる口」を 1 つずつ書きます(doeff-hy の defeffect が macro で生やしている物を手で書く形。macro で同じ 5 行に畳めます)。

2. record・enum・契約 defrecord → case class、defenum → enum、:pre/:post → 引数と戻りの型

今の Hy

(defrecord InputRow

(#^ str id)
(#^ int version)
(#^ InputState state)

"判断 1 つ = 書き(高々 1 つ・None = 書かない)と結末。"

(#^ (| InputDone InputRejected) outcome))

;; 契約は defk の map で実行時に検査

Scala 3 + Kyo

/** ReadInput の答え: id = 入力の id・version = 本文の行の版 … */
case class InputRow(id: String, version: Int, state: InputState,
editId: Maybe[String], editCount: Int)
/** 判断 1 つ = 書き(高々 1 つ・Absent = 書かない)と結末。 */
case class Judgment(write: Maybe[InputCreate | InputRevise | InputWithdraw],
outcome: InputDone | InputRejected)
enum RunOutcome:
case Done, Rejected, Deferred
// 契約は型そのもの — 実行時の検査も linter の契約の検査も要らない
def judged(request: InputRequest): Maybe[Judgment] < ReadInput
Maybe は Kyo が持つ型で、値は Present(x) か Absent。doeff の Absent と同じ語です。:pre が型の注釈でない述語(例: 長さ・範囲)なら require か精錬型(Iron)で書きます。

Scala 3 + Kyo(直接形)

/** 名指した行を読んで判じるため。読めなかった(届かない)= Absent(この周は見送る)。 */
@context("messaging") @role("program")
def judged(request: InputRequest): Maybe[Judgment] < ReadInput = defer:
targetOf(request) match // 純粋(effect 無し)なら印は要らない
case Absent => Present(judge(request, Absent))
case Present(id) =>
ReadInput(id).now match // ← doeff の (<- answer … (ReadInput id))
case InputUnreadable(_, _) => Absent // この周は見送る
case r: InputRow => Present(judge(request, Present(r)))
case InputAbsent(_) => Present(judge(request, Absent))
/** 要求 1 つを実体化して結末を積むため。… */
@context("messaging") @role("program")
def runInputRequest(request: InputRequest)
: RunOutcome < (ReadInput & WriteInput & SettleIntake) = defer:
val outcome = outcomeOf(request).now // : Maybe[InputDone | InputRejected]
outcome match
case Absent => RunOutcome.Deferred
case Present(out) =>
val settlement = settlementOf(request.requestId, RouteInput, out)
SettleIntake(settlement).now match
case IntakeSettleLanded() => out match
case InputDone(_) => RunOutcome.Done
case InputRejected(_, _) => RunOutcome.Rejected
case IntakeSettleRefused(_) | IntakeUnreachable(_) => RunOutcome.Deferred
effect の並びは型に載る: RunOutcome < (ReadInput & WriteInput & SettleIntake)。outcomeOf が使う ReadInput & WriteInput と、この関数が直に使う SettleIntake の和を compiler が推論し、宣言した型より多ければ compile が止まります(下の 6)。 :effects [ReadInput WriteInput SettleIntake] の手書きと linter の突合が、そのまま型検査になります。
直接形と for 形: 上は defer { … .now } の直接形。for 形(for { o <- outcomeOf(request); … } yield …)も書けますが、doeff の <- の読みに近いのは直接形です。

3b. 書き方 3 つ — 印の数は doeff の <- と同じ for 構文は要らない

Kyo は for 構文を要求しません。defer(macro)の中では純粋な式は普通の Scala で、effect を持つ呼びにだけ .now を付けます。 印の数 = doeff で <- を書く行の数。for 構文(3 列目)を使った時だけ「1 行ごとの持ち上げ」が要り、if・match・早い return が中に入ると入れ子になります。

(defk run-input-request [request]

(when (is outcome None)
(return RunOutcome.DEFERRED))
(<- settlement IntakeSettlement (settlement-of …))

_ RunOutcome.DEFERRED))

case Absent => RunOutcome.Deferred
case Present(out) =>

SettleIntake(settlement).now match

Kyo for 形(持ち上げが要る — 使わない)

def runInputRequest(request: InputRequest)

書きたい物doeff(generator)Kyo defer

印を 1 つも書きたくないなら、それは monad の library では無理で、言語が effect を持つ必要があります。その形は 2 つあります。
1. Scala 本流の向き: capability(def judged(request: InputRequest)(using ReadInput): Maybe[Judgment]、本体は ReadInput.read(id) と書くだけ)+ capture checking で型に載せる。Scala 3.4+ の実験機能(-language:experimental.captureChecking)で、handler の再開は Loom の継続(JDK 21+)で作る。まだ実験段階。
2. effect を持つ言語: Effekt(def judged(request: InputRequest): Maybe[Judgment] / {ReadInput}、本体は do ReadInput(id))・Flix(def judged(request: InputRequest): Maybe[Judgment] \ ReadInput)・Koka(fun judged(request) : readinput maybe<judgment>)。どれも印無しで effect が型に載る。代わりに生態系と Python の呼び出しが弱い(前の返事の表)。

4. handler defhandler → run の入れ子。本番は ScalaPy で Python を呼び、テストは Map で偽る

今の Hy(protocol/conversation_input.hy:132)

(defhandler conversation-input-store
{:effects [ReadRow PutRow PlaceInput ReadPlacedInput WithdrawPlacedInput]
:tags {:context "messaging" :role "protocol"}}
;; 入力の行の読み書きを、置いた入力の本文の表と置いた側の台帳の口で答える。
(ReadInput [id]
(<- answer (| InputRow InputAbsent InputUnreadable) (read-input id))
(resume answer))
(WriteInput [write]
(<- answer (| WriteLanded WriteConflict WriteRefused WriteUnreachable) (write-input write))
(resume answer)))

Scala 3 + Kyo

/** 本番: ReadInput / WriteInput を、下の層の effect(ReadRow・PutRow …)へ翻訳して答える */
@context("messaging") @role("protocol")
def conversationInputStore[A, S](v: A < (ReadInput & WriteInput & S))
: A < (ReadRow & PutRow & PlaceInput & ReadPlacedInput & WithdrawPlacedInput & S) =
WriteInput.run(w => writeInput(w))(
ReadInput.run(id => readInput(id))(v)) // readInput: String => ReadAnswer < (ReadRow & ReadPlacedInput)
/** 一番外の層: 行の読み書きを Python(sqlite3 / httpx)で行う。ScalaPy で CPython を呼ぶ */
import me.shadaj.scalapy.py
object PyStore:
private val sqlite = py.module("sqlite3")
private val conn = sqlite.connect("inputs.db")
def readRow(id: String): RowAnswer =
val cur = conn.execute("select version, state, edit_id, edit_count from inputs where id = ?", Seq(id).toPythonProxy)
val hit = cur.fetchone()
if py.Dynamic.global.`None`.equals(hit) then RowAbsent(id)
else Row(id, hit.bracketAccess(0).as[Int], InputState.valueOf(hit.bracketAccess(1).as[String]),
Maybe.fromOption(hit.bracketAccess(2).as[Option[String]]), hit.bracketAccess(3).as[Int])
def pyRowStore[A, S](v: A < (ReadRow & S)): A < (Sync & S) =
ReadRow.run(id => Sync.defer(PyStore.readRow(id)))(v) // Python 呼び出しは Sync の中(副作用の印)
/** テストの偽物: Map で答える。effect が 1 つ消えるだけで、他の層は触らない */
def fakeStore[A, S](rows: Map[String, InputRow])(v: A < (ReadInput & S)): A < S =
ReadInput.run(id => rows.get(id).fold[ReadAnswer](InputAbsent(id))(identity))(v)
handler は「A < (E & S) を受けて A < S' を返す関数」で、何を消して何を足すかが型に出ます(conversationInputStore は ReadInput・WriteInput を消し、ReadRow・PutRow … を足す)。 doeff の「環境の違いは handler の組という値だけで表す」がそのまま成り立ち、しかも組み合わせが足りなければ compile で分かります。 Python は一番外の handler の中だけに置き(Sync で包む)、Program と中の handler は Python を知りません。ScalaPy の py.Dynamic は動的な値なので、境界で .as[T] により Scala の型へ写します(pyo3 の extract::<T>() と同じ形)。
