# DOEFF101〜108: 層の規則(Hy と Python)

業務の判断を持つ純粋な層と、外の世界に触る層を分ける決まりを判じる規則。層の名前・role・環境の語は repo の設定から受け取る
(設定の書き方と判じ方の細部は [../SPECIFICATION.md](../SPECIFICATION.md))。下の例は次の設定を前提にする。

```toml
[tool.doeff-linter.layers]
order = ["core", "intent", "foundation", "entry"]
paths = { core = "app/core", intent = "app/intent", foundation = "app/foundation", entry = "app/entry" }
types_only = ["intent"]
[tool.doeff-linter.layers.allow_imports]
core = ["core", "intent"]
[tool.doeff-linter.layers.forbid_modules]
core = ["httpx", "subprocess"]
[tool.doeff-linter.roles.by_layer]
core = ["judgment", "type"]
[tool.doeff-linter.raw_side_effects]
allowed_layers = ["foundation", "entry"]
[tool.doeff-linter.environment_names]
words = ["fake", "local", "wire"]
paths = ["app/billing"]
assembly_files = ["handler_sets.hy"]
```

## DOEFF101 Layer Import Direction

層の module は、`allow_imports` で許した層の module だけを import する。repo の外(doeff・標準の library)の import は数えない。

```hy
;; 悪い: app/core/charge.hy(core は intent だけを読む)
(import app.foundation.io [send])
;; 良い
(import app.intent.charge [Charge])
```

```python
# 悪い: app/core/charge.py
from app.foundation.io import send
```

## DOEFF102 Layer Forbidden Module

層ごとに禁じた module(I/O の module など)を直に import しない。関数の中の import も数える。

```hy
;; 悪い: app/core/net.hy
(import httpx)
```

```python
# 悪い: app/core/proc.py
def run():
    import subprocess
```

## DOEFF103 Types-Only Layer

`types_only` の層には型だけを置き、関数と handler を定めない。

```hy
;; 悪い: app/intent/charge.hy
(defclass Charge [])
(defk decide [x] {:pre [] :post []} x)
;; 良い: 型だけ
(defclass Charge [])
```

## DOEFF104 Module Declares Tags

層の module の定義は、定義の `:tags` か module の頭のタグで文脈(context)と役(role)を名乗る。

```hy
;; 悪い
(defn decide [x] x)
;; 良い(module の頭のタグ)
(val MODULE-TAGS {:context "billing" :role "judgment"})
(defn decide [x] x)
;; 良い(定義ごとのタグ)
(defk plan [x] {:pre [] :post [] :tags {:context "billing" :role "judgment"}} x)
```

```python
# 良い
MODULE_TAGS = {"context": "billing", "role": "judgment"}
```

## DOEFF105 Role Matches Layer

タグの role はその層で許された物で、context も名乗る。

```hy
;; 悪い: app/core/peer.hy(core に translation の役は置けない)
(val MODULE-TAGS {:context "billing" :role "translation"})
```

```python
# 悪い: context が無い
MODULE_TAGS = {"role": "judgment"}
```

## DOEFF106 Raw Side Effect Placement(Hy)

生の副作用(http・時刻・乱数・file・process・環境変数 …)に直に触る定義は、`allowed_layers` の層にだけ置く。証拠は
doeff-indexer の hy-index 版 3(目録 `data/raw_side_effects.json`)。import を通した名前と組み込みは強い証拠で error、
method 名だけで見つけた証拠は弱い証拠で warning。

```hy
;; 悪い: app/core/clock.hy
(import time)
(defn now [] (time.time))
;; 良い: 時刻は effect を出して foundation の handler に答えさせる
```

## DOEFF107 Raw Side Effect Via Call(Hy・info)

呼ぶ定義を通して生の副作用に届く定義を、経路つきで知らせる(違反ではない)。全体の実行だけが出す。

```hy
;; app/core/clock.hy: later は now を通して time.time に届く
(defn later [] (now))
```

## DOEFF108 Environment Name In Business Code

業務の file の名と、handler(defhandler・`[effect k]` を受ける関数)・組み立ての file の関数の名に環境の語を付けない。
名を `-`・`_`・`.` で切った語で比べる(`wireless` は `wire` に当たらない)。大文字だけの定数の名は見ない。

```hy
;; 悪い: app/billing/handlers_fake.hy(file の名と handler の名)
(defhandler fake-charge [] …)
;; 悪い: app/billing/handler_sets.hy
(defn wire-handlers [] […])
;; 良い: 仕組みの名にする
(defhandler charge-translation [] …)
```

## 既知の破れと照合中

- 登録簿(`[tool.doeff-linter.registry] dirs / files`)に鍵が載った破れは warning(`registered: true`)。
- `reconciling` に書いた規則の違反は info(既存の検査と並べて差を見ている間)。
- `noqa` の註は層の規則には効かない。
