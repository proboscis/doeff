# DOEFF101-108: Layer rules (Hy and Python)

Rules that judge the convention separating pure layers that hold business judgment from layers that touch the outside world. Layer names, roles, and environment words are taken from the repo's settings
(see [../SPECIFICATION.md](../SPECIFICATION.md) for the details of how to write the settings and how judgments are made). The examples below assume the following settings.

```toml
[tool.doeff-linter.layers]
order = ["core", "intent", "foundation", "entry"]
paths = { core = "app/core", intent = "app/intent", foundation = "app/foundation", entry = "app/entry" }
types_only = ["intent"]
[tool.doeff-linter.layers.allow_imports]
core = ["core", "intent"]
[tool.doeff-linter.layers.forbid_modules]
core = ["httpx", "subprocess"]
[tool.doeff-linter.roles.by_layer]
core = ["judgment", "type"]
[tool.doeff-linter.raw_side_effects]
allowed_layers = ["foundation", "entry"]
[tool.doeff-linter.environment_names]
words = ["fake", "local", "wire"]
paths = ["app/billing"]
assembly_files = ["handler_sets.hy"]
```

## DOEFF101 Layer Import Direction

A layer's module may import only modules of the layers allowed by `allow_imports`. Imports from outside the repo (doeff, the standard library) are not counted.

```hy
;; Bad: app/core/charge.hy (core reads only intent)
(import app.foundation.io [send])
;; Good
(import app.intent.charge [Charge])
```

```python
# Bad: app/core/charge.py
from app.foundation.io import send
```

## DOEFF102 Layer Forbidden Module

Do not import directly a module forbidden for the layer (such as I/O modules). Imports inside functions are counted too.

```hy
;; Bad: app/core/net.hy
(import httpx)
```

```python
# Bad: app/core/proc.py
def run():
    import subprocess
```

## DOEFF103 Types-Only Layer

Put only types in a `types_only` layer, and define no functions or handlers.

```hy
;; Bad: app/intent/charge.hy
(defclass Charge [])
(defk decide [x] {:pre [] :post []} x)
;; Good: types only
(defclass Charge [])
```

## DOEFF104 Module Declares Tags

Definitions in a layer's module declare their context and role through the definition's `:tags` or the tags at the head of the module.

```hy
;; Bad
(defn decide [x] x)
;; Good (tags at the head of the module)
(val MODULE-TAGS {:context "billing" :role "judgment"})
(defn decide [x] x)
;; Good (tags per definition)
(defk plan [x] {:pre [] :post [] :tags {:context "billing" :role "judgment"}} x)
```

```python
# Good
MODULE_TAGS = {"context": "billing", "role": "judgment"}
```

## DOEFF105 Role Matches Layer

The role in the tags must be one allowed in that layer, and the context must be declared too.

```hy
;; Bad: app/core/peer.hy (a translation role cannot be placed in core)
(val MODULE-TAGS {:context "billing" :role "translation"})
```

```python
# Bad: no context
MODULE_TAGS = {"role": "judgment"}
```

## DOEFF106 Raw Side Effect Placement (Hy)

A definition that directly touches raw side effects (http, time, randomness, files, processes, environment variables, ...) is placed only in the layers of `allowed_layers`. The evidence is
doeff-indexer's hy-index version 3 (catalog `data/raw_side_effects.json`). Names reached through an import and builtins are strong evidence and give an error;
evidence found only by a method name is weak evidence and gives a warning.

```hy
;; Bad: app/core/clock.hy
(import time)
(defn now [] (time.time))
;; Good: emit an effect for the time and let the foundation handler answer it
```

## DOEFF107 Raw Side Effect Via Call (Hy, info)

Reports, with the path, a definition that reaches a raw side effect through the definitions it calls (not a violation). Only a whole-project run emits it.

```hy
;; app/core/clock.hy: later reaches time.time through now
(defn later [] (now))
```

## DOEFF108 Environment Name In Business Code

Do not put environment words in the names of business files, nor in the names of functions in handlers (defhandler, and functions that take `[effect k]`) or assembly files.
Names are compared by the words obtained by splitting on `-`, `_`, and `.` (`wireless` does not match `wire`). Constant names that are all uppercase are not checked.

```hy
;; Bad: app/billing/handlers_fake.hy (file name and handler name)
(defhandler fake-charge [] …)
;; Bad: app/billing/handler_sets.hy
(defn wire-handlers [] […])
;; Good: name it by its mechanism
(defhandler charge-translation [] …)
```

## Known violations and reconciling

- A violation whose key is listed in the registry (`[tool.doeff-linter.registry] dirs / files`) is a warning (`registered: true`).
- Violations of rules listed in `reconciling` are info (while the difference is being compared against the existing checks).
- A `noqa` comment has no effect on the layer rules.
